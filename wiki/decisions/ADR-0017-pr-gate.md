# ADR-0017 · main은 PR과 CI를 통과한 것만 받는다

```yaml
id: ADR-0017
status: accepted
statement: main 브랜치를 보호해 직접 푸시를 막고, PR과 CI 통과를 병합 조건으로 강제한다. 리뷰 승인은 요구하지 않고, 관리자도 우회하지 않는다. 병합은 merge commit으로 한다.
confidence: 기록됨
source:
  - wiki/git.md 2절
  - .github/PULL_REQUEST_TEMPLATE.md
  - .github/workflows/ci.yml
```

## 맥락

규칙을 정하기 전 `main`에는 **아무 보호도 걸려 있지 않았다**(`branches/main/protection` → 404). CI는 PR과 `main` 푸시에서 돌지만 **결과가 병합을 막지 않았다.** 즉 타입체크가 깨진 커밋도, PR을 거치지 않은 커밋도 `main`에 들어갈 수 있었다.

이 저장소에서 그것이 유독 위험한 이유가 하나 있다. **`main`에 들어간 것은 사용자에게 자동으로 나간다** — CI가 성공하면 OTA 발행 워크플로가 이어서 돈다([`POL-RELEASE-001`](../policy/POL-RELEASE.md)). 서버가 없어서 되돌릴 중간 지점도 없다. `main`이 곧 배포다.

## 결정

GitHub 브랜치 보호로 **PR 경유**와 **CI 통과**를 강제한다. 리뷰 승인 수는 0이다 — 1인 저장소에서 GitHub은 본인 PR을 본인이 승인하도록 허용하지 않으므로, 승인 1을 요구하면 아무것도 머지할 수 없다. 관리자 우회(`enforce_admins`)는 끈다.

병합은 merge commit을 유지한다.

## 대안

- **보호 없이 규칙만 문서화.** 급할 때 직푸시할 여지가 남는다. 그러나 지키지 않아도 아무 일이 없는 규칙은 이미 이 저장소에서 어긋난 전례가 있다(`feat/` vs `feature/` 접두 혼재). 문서만으로는 안 지켜진다는 증거가 저장소 안에 있다.
- **관리자 우회 허용.** 비상구를 남기는 절충안. 채택하지 않았다 — 우회가 필요할 만큼 급한 상황이 곧 검사가 가장 필요한 상황이다. 정말 막히면 보호를 잠시 끄는 편이 낫다. 그 행위는 로그에 남고, 우회는 남지 않는다.
- **squash 머지.** `main` 히스토리가 PR 하나당 커밋 하나로 깔끔해진다. 커밋 컨벤션의 실질 대상이 PR 제목으로 옮겨가고 작업 중 커밋이 자유로워지는 이점이 있다. 히스토리 단위를 유지하기 위해 채택하지 않았고, 대신 **푸시 전 rebase 정리**를 규칙으로 세웠다.
- **리뷰 승인 필수.** 지금은 물리적으로 불가능하다. 기여자가 둘 이상이 되면 이 결정을 다시 연다.

## 귀결

- 워크트리에서 작업하다 `main`에 바로 커밋하던 습관은 이제 막힌다([`ADR-0014`](ADR-0014-worktree-workflow.md)와 같은 방향이다).
- 필수 검사 이름은 CI 워크플로의 **잡 이름 `Typecheck, lint & test`** 에 묶인다. 잡 이름을 바꾸면 보호 규칙이 존재하지 않는 검사를 기다리며 **모든 PR이 영원히 병합 불가**가 된다. 잡 이름을 바꿀 때는 보호 설정도 같이 고친다.
- strict 모드라 `main`이 앞서 나가면 브랜치를 최신화해야 검사가 다시 돈다. 1인 저장소에서는 대부분 문제가 되지 않는다.
- 리뷰 승인이 0이므로 **PR은 리뷰 도구가 아니라 CI 게이트이자 롤백 단위**다. PR 템플릿을 짧게 유지하는 이유도 같다.
