# ADR-0012 · 로컬 전용 — 계정도 서버도 관측도 없다

```yaml
id: ADR-0012
status: accepted
statement: 백엔드·계정·동기화·애널리틱스를 두지 않는다. 그 결과 운영 관측(trace/metric)으로 회귀를 잡는 증거 계층이 존재하지 않는다.
confidence: 기록됨
source:
  - DESIGN.md "Constraints" (로컬 저장 V1 — 서버·계정 없음)
  - docs/legal/privacy-policy.md 2, 4장
  - docs/store/store-listing.md (Data Safety — No data collected)
```

## 맥락

사이드 프로젝트의 출시 속도, 오프라인 우선 요구, 그리고 "내 데이터는 내 기기에"라는 제품 약속이 같은 방향을 가리켰다. 스토어 제출 시 "데이터 수집 없음"으로 신고하면서 이 결정은 **공개 약속**이 되었다.

## 결정

네트워크 통신은 EAS Update 확인 하나뿐. 사용자 콘텐츠·식별자·사용 기록을 어디에도 보내지 않는다.

## 귀결 — 좋은 쪽

- 비행기 모드에서 앱 전체가 동작한다. 예배실·지하에서 기능 저하가 없다.
- 개인정보 처리 부담이 사실상 없다. 스토어 심사 항목이 단순해진다.
- 서버 비용과 운영이 없다.

## 귀결 — 비용

- **관측 증거 계층이 없다.** 크래시율, 저장 실패율, 자동완성 성공률 같은 신호를 볼 수 없다. 규칙에 `observed_by: metric`을 적을 방법이 없고, 이 위키의 증거는 자동 테스트·수동 QA·내보낸 파일 세 가지로 한정된다([`README.md` 4절](../README.md)).
- 결함은 사용자가 말해 주기 전까지 발견되지 않는다.
- 기기를 잃으면 데이터도 잃는다. 유일한 방어가 수동 내보내기인데, 그 절반(전체 백업)이 아직 없다([`RULE-MD-008`](../rules/share-markdown.md)).
- 여러 기기에서 같은 노트를 이어 쓸 수 없다. `DESIGN.md` P4가 이를 "V2의 명시적 의제"로 남겨 두었다.

## 이 결정을 뒤집으려면

관측을 도입하는 어떤 변경도 [`POL-PRIVACY-001`](../policy/POL-PRIVACY.md)과 **스토어에 제출한 신고 내용**을 함께 바꿔야 한다. 코드만 바꾸는 것으로 끝나지 않는다.
