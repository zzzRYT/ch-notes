# 작업 절차 — 정본 먼저

이 저장소에서 무슨 일을 하든 **코드를 열기 전에 정본을 확인한다.** 기능 추가, 버그 수정, 리팩터링, 배포 모두 같다.

이 위키는 *결정이 기록된 적 없이 코드에만 남아 있던 것*을 역으로 정리해 만든 것이다. 대조 없이 코드부터 손대면 위키가 다시 뒤처지고, 위키를 만든 이유가 사라진다.

---

## 다섯 단계

### 1. 찾는다

[`by-task.md`](by-task.md)에서 **작업 유형** 또는 **건드릴 코드 경로**로 진입점을 찾는다. 거기에 그 영역의 `POL`·`RULE`·`CONTRACT`·`ADR`과 코드·테스트 경로, 알려진 함정이 모여 있다.

없으면 폴더 인덱스로 간다 — [`policy/`](policy/index.md) · [`rules/`](rules/index.md) · [`contracts/`](contracts/index.md) · [`decisions/`](decisions/index.md).

### 2. 대조한다

찾은 블록의 `statement`를 `implemented_by` 코드와 맞춰본다. **지금 코드가 정말 그렇게 동작하는지**를 본다.

`verified_by`의 테스트도 열어본다. **테스트 이름을 믿지 않는다** — 이 저장소에는 이름과 검증 내용이 다른 테스트가 실재한다([`drift.md`](drift.md) C절). 이름이 아니라 본문이 그 `statement`를 검증하는지 확인한다.

### 3. 어긋나면 위키를 먼저 고친다

**코드가 정본이다.** 위키가 코드와 다르면 위키가 틀린 것이다. 작업을 시작하기 전에 위키를 현재 코드에 맞춘다.

- 계획 문서(`DESIGN.md`, `docs/plans/**`)와 어긋난 것이면 [`drift.md`](drift.md) A절에 남긴다.
- 왜 그렇게 되어 있는지 모르겠으면 **지어내지 않는다.** `confidence: 확인필요`로 두고 [`drift.md`](drift.md) E절에 질문으로 남긴다.

이 단계를 건너뛰면 틀린 전제 위에서 작업하게 된다. 위키가 있어서 더 위험하다 — 사람은 적혀 있는 것을 믿는다.

### 4. 작업한다

워크트리 안에서([`ADR-0014`](decisions/ADR-0014-worktree-workflow.md)). 검증도 그 안에서.

### 5. 같은 변경에서 위키를 갱신한다

동작을 바꿨으면 관련 `RULE`/`CONTRACT`를 **같은 커밋에서** 고친다. 나중에 하는 것은 안 하는 것이다.

```bash
node wiki/check.mjs      # 필수 — 통과해야 한다
node wiki/gen-index.mjs  # 블록을 더하거나 requirement/confidence를 고쳤으면
```

새 결정을 내렸으면 `ADR`을 추가한다. **결정의 이유를 그때 적는다.** 이 위키가 존재하는 이유가 그것이다 — 나중에는 아무도 기억하지 못한다.

## 무엇을 어디에 적는가

| 적을 것 | 계층 | 예 |
|---|---|---|
| 사용자에게 하는 약속 | [`POL`](policy/index.md) | "인터넷 없이 구절이 들어온다" |
| 항상 참이어야 하는 동작 | [`RULE`](rules/index.md) | "참조 뒤 space가 인용을 확정한다" |
| 깨면 데이터·파일·배포가 깨지는 경계 | [`CONTRACT`](contracts/index.md) | `body_json` 컬럼, `.md` frontmatter |
| 왜 그렇게 정했는지 | [`ADR`](decisions/index.md) | "Tab 대신 space" |
| 어긋난 것·모르는 것 | [`drift.md`](drift.md) | 계획↔구현 차이, 확인필요 질문 |

판단이 서지 않으면: **약속이면 POL, 검증할 수 있으면 RULE, 남이 의존하는 모양이면 CONTRACT, 되돌릴 수 있었던 선택이면 ADR.**

블록 형식과 ID 규칙은 [`README.md`](README.md) 3·4절.

## 검사기가 막는 것

`node wiki/check.mjs`는 위키가 조용히 썩는 것을 막는다. 통과한다고 위키가 옳다는 뜻은 아니다 — **연결이 끊기지 않았다**는 뜻이다.

| 검사 | 막는 것 |
|---|---|
| ID 유일성 | 같은 ID를 두 번 발급 |
| `policy:` 실재 | 없는 정책을 가리키는 규칙 |
| 경로 실재 | 파일이 옮겨졌는데 위키가 옛 경로를 가리킴 |
| `verified_by`의 `#조각` 실재 | 증거로 지목한 테스트 이름이 사라짐 |
| 증거 없는 `MUST` | 검증되지 않는 것을 검증된 것처럼 씀 |
| 폴더 인덱스 완전성 | 파일·규칙을 더하고 인덱스를 안 고침 |
| 산문 ID 실재 | 오타 난 ID, 삭제된 ID를 가리키는 링크 |
| 링크 대상 실재 | 없는 문서를 가리키는 안내 |
| 생성기 커버리지 | 새 `RULE` 계열이 `index.md`에서 조용히 빠짐 |
| 안내 경로 실재 | 코드가 옮겨졌는데 `by-task.md`가 옛 경로를 안내 |

검사기가 잡지 못하는 것: **statement가 실제 동작과 맞는지.** 그건 2단계에서 사람이 한다.

## 이 절차를 건너뛰어도 되는 때

없다. 다만 **읽는 양은 작업 크기에 맞춘다** — 오타 하나 고치는 데 `by-task.md` 한 줄만 보고 끝나도 된다. 1단계를 건너뛰지 않는 것이 핵심이지, 매번 전부 읽으라는 뜻이 아니다.
