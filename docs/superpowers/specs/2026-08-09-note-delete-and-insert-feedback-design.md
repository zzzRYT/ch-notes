# 노트 삭제 및 성경 인용 추가 피드백 설계

## 배경

노트 저장소에는 영구 삭제 기능이 있지만 이를 호출하는 화면 동작이 없다. 또한 성경의 절 옆 `+` 버튼은 인용 블록을 노트에 추가하지만 성공 여부를 화면에 알리지 않는다. 사용자는 노트를 정리할 수 없고, 인용을 여러 번 누르거나 추가 여부를 확인하기 위해 성경 화면을 닫아야 한다.

## 목표

- 휴대폰과 태블릿에서 노트를 삭제할 수 있다.
- 목록에서는 각 노트 행을 왼쪽으로 밀어 삭제 동작을 드러낼 수 있다.
- 편집 화면에서도 현재 노트를 삭제할 수 있다.
- 삭제 직후 5초 동안 실행 취소할 수 있다.
- 성경 인용 추가의 성공 또는 실패를 성경 화면을 닫지 않고 확인할 수 있다.

## 범위 밖

- 앱을 종료하거나 다시 실행한 뒤 삭제를 취소하는 기능
- 휴지통, 삭제 기록, 다중 선택 삭제
- DB 스키마에 삭제 상태를 저장하는 소프트 삭제
- 인용 블록의 중복 여부를 판단하거나 중복 추가를 막는 기능

## 사용자 흐름

### 목록에서 삭제

1. 사용자가 노트 한 행을 왼쪽으로 민다.
2. 행 오른쪽에 빨간색 `삭제` 동작이 나타난다.
3. 사용자가 `삭제`를 누르면 노트가 DB와 현재 목록에서 즉시 사라진다.
4. 화면 아래에 `노트를 삭제했습니다`와 `실행 취소`가 5초 동안 표시된다.
5. 사용자가 `실행 취소`를 누르면 같은 ID, 내용, 메타데이터와 타임스탬프로 노트가 복원되고 원래 정렬 위치에 나타난다.

스와이프를 수행하기 어려운 사용자를 위해 드러난 삭제 동작은 독립적인 접근성 버튼으로 탐색하고 실행할 수 있어야 한다. 한 번에 하나의 행만 열린 상태를 유지한다.

### 편집 화면에서 삭제

1. 휴대폰 편집 화면 상단과 태블릿 편집 영역 상단에 휴지통 버튼을 제공한다.
2. 사용자가 버튼을 누르면 현재 노트를 즉시 삭제한다.
3. 휴대폰은 노트 목록으로 이동한다. 태블릿은 삭제한 노트를 목록에서 제거하고 다음 최신 노트를 선택하며, 남은 노트가 없으면 빈 상태를 표시한다.
4. 화면 아래에 목록 삭제와 동일한 실행 취소 안내가 표시된다.
5. 실행 취소 시 노트를 복원하고 목록에 다시 표시한다. 태블릿에서는 복원한 노트를 다시 선택한다. 휴대폰은 목록에 머문다.

### 삭제 실행 취소

삭제는 즉시 DB에 반영하고, 삭제 직전의 완전한 `Note` 스냅샷을 메모리에 5초 동안 보관한다. 실행 취소는 이 스냅샷을 저장소에 다시 삽입한다. 복원은 ID, 제목, 본문, 인용, 설교 날짜, 설교자, 장소, 대표 성경 구절, 생성일과 수정일을 모두 보존한다.

새 삭제가 발생하면 안내와 실행 취소 대상은 가장 최근에 삭제한 노트로 교체된다. 앞서 삭제한 노트는 삭제된 상태로 확정된다. 앱 종료 시 보관 중인 스냅샷은 사라지며 삭제는 유지된다.

삭제 또는 복원에 실패하면 UI 상태를 DB 결과와 맞추고 `노트를 삭제하지 못했습니다` 또는 `노트를 복원하지 못했습니다`를 표시한다. 존재하지 않는 노트의 삭제 요청은 실패 안내로 처리하되 앱을 중단시키지 않는다.

## 성경 인용 추가 피드백

성경 절 옆 `+`를 누르면 기존 동작대로 해당 절을 현재 노트 끝에 인용 블록으로 추가하고 빈 문단을 뒤에 둔다. 성공하면 화면 아래에 `<표시용 성경 구절>을 노트에 추가했습니다`를 3초 동안 표시한다. 예시는 `요한복음 3:16을 노트에 추가했습니다`이다.

안내 때문에 성경 모달이나 패널을 닫지 않는다. 사용자가 다른 절을 연속으로 추가하면 가장 최근 구절로 문구를 바꾸고 3초 타이머를 다시 시작한다. 구절 조회에 실패하면 본문을 변경하지 않고 `성경 구절을 추가하지 못했습니다`를 오류 스타일로 표시한다.

휴대폰 편집 화면의 성경 모달과 태블릿 성경 패널 모두 같은 문구와 시간 규칙을 사용한다. 안내 영역은 화면 읽기 도구가 상태 변경을 읽도록 live region 역할을 제공한다.

## 구성 요소와 책임

### 공용 액션 배너

일반 안내, 오류 안내, 선택적인 액션 버튼과 자동 닫힘 시간을 입력받는 작은 공용 컴포넌트를 둔다. 삭제 안내에는 `실행 취소` 액션을, 인용 안내에는 문구만 전달한다. 타이머가 교체되거나 컴포넌트가 해제될 때 이전 타이머를 정리한다.

### 삭제 상태 조정

화면 이동 뒤에도 삭제 안내와 실행 취소가 유지되어야 하므로 삭제 스냅샷과 만료 시각을 앱 상태 계층에서 관리한다. DB 작업 자체는 저장소가 담당하고, 상태 계층은 가장 최근 작업과 UI에 노출할 피드백만 관리한다. 화면은 삭제 성공 이후 목록과 선택 상태를 갱신한다.

편집 중인 노트를 삭제할 때는 해당 노트의 자동 저장을 먼저 중단한 뒤 삭제한다. 삭제 완료 뒤 예약되어 있던 저장이 실행되어 삭제된 노트를 갱신하려 하거나 오류 안내를 덮어쓰지 않아야 한다. 실행 취소로 복원한 뒤에만 해당 노트의 자동 저장을 다시 허용한다.

### 노트 저장소

기존 `delete(id)`를 사용하되, 삭제 대상이 실제로 존재했는지 호출자가 알 수 있는 계약을 제공한다. 실행 취소용 복원 동작은 완전한 `Note`를 받아 기존 ID와 모든 타임스탬프를 보존해 삽입한다. 동일 ID가 이미 존재하면 덮어쓰지 않고 실패한다.

### 스와이프 행

휴대폰 `NoteCard`와 태블릿 사이드바 항목이 공유할 수 있는 얕은 행 래퍼를 둔다. 이 래퍼는 수평 제스처, 삭제 동작 노출, 열린 행 닫기와 접근성만 담당하며 노트 데이터나 DB를 알지 않는다. 웹의 포인터 드래그와 모바일 터치를 모두 지원하는 프로젝트의 React Native 입력 방식을 사용한다.

### 인용 추가 결과

인용 삽입 함수는 성공 여부를 명시적으로 반환하거나 성공·실패 콜백을 발생시킨다. 휴대폰과 태블릿 컨테이너는 그 결과를 받아 공용 배너를 표시한다. `VerseList`는 추가 요청만 전달하고 노트 편집 상태나 안내 상태를 직접 소유하지 않는다.

## 데이터 흐름

```text
목록 스와이프/편집기 휴지통
  → 현재 Note 스냅샷 조회
  → 저장소 영구 삭제
  → 목록·선택 상태 갱신
  → 5초 실행 취소 배너 등록
      └ 실행 취소 → 저장소 복원 → 목록·선택 상태 갱신

성경 절 + 버튼
  → 구절 조회
  → 성공: 본문에 인용 블록 추가 → 3초 성공 배너
  └ 실패: 본문 유지 → 오류 배너
```

## 테스트 및 검증

자동 검증은 다음을 포함한다.

- 저장소가 노트를 삭제하고 다시 조회되지 않게 하는지 검증
- 저장소 복원이 모든 필드와 생성·수정 타임스탬프를 보존하는지 검증
- 중복 ID 복원이 기존 노트를 덮어쓰지 않는지 검증
- 삭제 상태가 가장 최근 삭제 스냅샷만 실행 취소 대상으로 유지하는지 검증
- 실행 취소 성공·실패와 만료 동작 검증
- 편집 중 삭제 후 예약된 자동 저장이 삭제된 노트에 실행되지 않는지 검증
- 인용 조회 성공 시 본문 변경과 성공 문구가 일치하는지 검증
- 인용 조회 실패 시 본문이 바뀌지 않고 오류 문구가 표시되는지 검증
- 연속 인용 추가 시 최신 문구로 교체되고 표시 시간이 갱신되는지 검증

수동 검증은 휴대폰과 태블릿 각각에서 다음을 확인한다.

- 노트 행을 왼쪽으로 밀어 삭제하고 5초 안에 복원
- 편집 중인 노트를 휴지통 버튼으로 삭제한 뒤 올바른 화면과 선택 상태 확인
- 실행 취소를 누르지 않았을 때 노트가 다시 나타나지 않음
- 성경 모달 또는 패널을 연 채 여러 절을 연속으로 추가하고 최신 성공 문구 확인
- 화면 읽기 도구가 삭제, 복원, 인용 성공과 실패 상태를 읽음

## 완료 조건

- 휴대폰과 태블릿의 목록 및 편집 영역에서 승인된 삭제 흐름이 동작한다.
- 삭제 즉시 반영과 5초 실행 취소가 데이터 손실이나 필드 변경 없이 동작한다.
- 휴대폰과 태블릿에서 인용 추가 성공·실패 안내가 승인된 문구와 시간 규칙으로 표시된다.
- 관련 저장소·상태·UI 테스트, 타입 검사와 린트가 통과한다.
