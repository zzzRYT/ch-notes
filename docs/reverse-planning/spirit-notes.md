# Spirit Notes 역기획 → 씀씀 도입 후보

- 조사일: 2026-09-23 · 대상: Spirit Notes 2.1 (3), iOS 26.3.1, 무료 플랜 · 도구: mobile-mcp (실기기 iPhone 12 mini)
- 범위: 설교 노트 작성 흐름, 저장, 씀씀에 없는 기능, 당장 구현 가능한 기능
- 이 문서는 조사 기록이다. 정본(`wiki/`)이 아니며, 도입이 결정되면 해당 POL/RULE로 옮긴다.

## 1. 작성 흐름

```
홈(사이드바) ─ Everything / Notes / Cards · Notebooks · Preachers · Tags
   │  하단: [Search]  [+ New Note]
   ▼
노트 목록 (All Notes) ─ 월별 그룹, 기본 정렬 = 수정일 (More → Select Notes / Sort: 수정일·작성일)
   │  [+] → 무료 5개 초과 시 페이월 모달 ("You've filled your 5 free notes")
   ▼
에디터
   ├ 헤더: [T] Title  ·  날짜 칩(23rd May 2026)
   ├       [Preacher ▾] (엔티티 선택/생성/검색)  ·  [Tags ▾]
   ├ 본문: "John 3:16 " 입력 → space 시 인용 카드로 치환 (카드 우상단에 번역본 NIV)
   ├ 키보드 툴바: [NIV 번역 전환] [사진: 촬영/앨범] [형광펜 4색] [B] [I] [U] [• 목록] [키보드 닫기]
   └ 상단: [● Record | 오디오 파일 가져오기]  [공유]
```

- **저장**: 저장 버튼이 없고 자동 저장된다(씀씀과 같음). 제목이 비어 있으면 목록에 **인용 참조를 이어 붙인 문자열**이 제목 대신 나온다("Genesis 1:1 요 3:16 John 3:16").
- **녹음 동기화(Pro)**: 녹음하면서 쓴 문단마다 녹음 시점 타임스탬프(0:41, 0:49…)가 왼쪽에 붙는다. 오디오는 클라우드에 저장되고, 다른 기기에서는 "Download Audio"로 받는다.
- **공유 시트**: Share Note(오디오·구절·타임스탬프·이미지를 포함한 링크), Print Note(서식 있는 인쇄/PDF), Export Audio.
- **성경 읽기**: 노트에 인용된 절은 회색으로 표시된다. 절을 탭하면 시트에 **"이 절을 인용한 노트 N개"**가 뜨고, `+`로 그 절에 노트나 카드를 붙인다.
- **카드**: 제목 없는 짧은 메모다. 작성 시각이 찍히고 태그를 달고 공유할 수 있다.
- **설정**: 화면 모드, 글자 크기(System), 녹음 품질, 기본 번역본.
- **검색**: 본문 전문 검색이 된다("그렇잖아요" → 해당 노트가 나옴).

### Spirit Notes의 약점 (씀씀이 이미 앞서는 곳)

| 항목 | Spirit Notes | 씀씀 |
|---|---|---|
| 한국어 참조 | `요 3:16 `를 인식하지 못함 | 한국어 정식·축약 66권 (POL-SCRIPTURE-001) |
| 한국어 번역본 | 없음 (영어 번역본만, 검색 "Korean" 0건) | 오프라인 한국어 본문 |
| 무료 한도 | 노트 5개, 이후 결제 | 제한 없음 |
| 설교 메타 | 제목·날짜·설교자·태그 | + 장소·생명양식 (POL-NOTE-002) |
| 프라이버시 | 클라우드 동기화 | 기기 밖으로 나가지 않음 (POL-PRIVACY-001) |

## 3. 도입 우선순위

판단 기준은 새 네이티브 의존성이 필요한지(OTA로 나갈 수 있는지), 스키마를 바꾸는지(RULE-OTA 전방 전용), 정책과 충돌하는지다.

### 지금 바로 가능 — JS만, 스키마 변경 없음, OTA 가능

| 순위 | 기능 | 규모 | 메모 |
|---|---|---|---|
| 1 | **G2 무제 노트 자동 제목** | XS | 목록 카드의 제목 대체값 = `citedRefs.join(" ")`. 표시만 바꾸고 저장하지 않는다 |
| 2 | **G3 정렬 옵션** | S | `updated_at` 컬럼이 이미 있음. settings.json에 정렬 기준 필드를 추가하면 all-or-nothing 검증이 걸리므로 기본값 처리에 주의 |
| 3 | **G1 본문 검색** | S | `body_text`에 `stripInlineMarks`로 만든 평문을 채운다. **ADR-0007을 뒤집는 결정**이라 ADR 갱신과 기존 노트 FTS 재색인(마이그레이션)이 필요 |

| 5 | **G5 설교자 자동완성** | S | `SELECT DISTINCT preacher`로 제안하고 스키마는 그대로 둔다. 설교자별 모아보기는 나중에 |
| 6 | **G6 형광펜** | M | inline mark에 `==text==` 추가(1색). Markdown 내보내기·가져오기의 왕복(POL-PORT-001)과 `stripInlineMarks` 수정이 함께 필요 |

### 다음 스토어 빌드에 묶을 것 — 새 네이티브 의존성

- **G7 인쇄/PDF**: `expo-print`. 오프라인에서 동작하므로 정책과 충돌하지 않는다. 내보낸 PDF에 성경 본문이 실리면 CC BY-SA 표시가 필요하다(POL-LICENSE-001).
- **G9 사진 삽입**: `expo-image-picker`와 새 블록 타입(`image`). 스키마·Markdown 포맷을 바꾸고 파일 저장소가 필요하다.
- ⚠ `ios/`·`android/`는 0.1.0 이후 다시 prebuild되지 않았다. 네이티브 모듈을 추가하기 전에 prebuild 상태부터 정리해야 한다.

### 보류 — 결정이 먼저 필요

- **G8 태그/노트북**: 스키마 변경(전방 전용 마이그레이션)이 필요하다. "어르신 UX"에 분류 체계가 필요한지부터 따져야 한다.
- **G10 녹음 동기화**: 네이티브 오디오, 마이크 권한, 기기 저장 용량 문제가 있다. 로컬 전용이면 프라이버시와는 충돌하지 않는다. Spirit Notes의 핵심 유료 기능이라 규모가 가장 크다.
- **G11 카드**: 노트와 역할이 겹친다. 사용자 요구가 확인되기 전까지 만들지 않는다.
- **G12 번역본 선택**: 기술 문제가 아니라 한국어 번역본 라이선스 문제다.

## 4. 추천 첫 묶음

**G2 + G3 + G1** 을 한 브랜치로 묶는다. 모두 목록·검색 경험("다시 찾는다", POL-NOTE-003)에 속하고, OTA로 배포할 수 있다. 정본 갱신 대상은 `wiki/policy/POL-NOTE.md`(POL-NOTE-003 문구), `wiki/rules/search.md`, `wiki/decisions/ADR-0007-fts-scope.md`다.

그다음은 **G4 구절 역링크**다. Spirit Notes에서 가장 "성경 노트 앱다운" 기능이고, 씀씀의 차별점인 오프라인 한국어 성경 위에 올리면 효과가 가장 크다.

- 대상은 같음(Spirit Notes, 무료 플랜, iPhone 12 mini). 기존 테스트 노트("하하하")에서 조작해 노트 할당량은 쓰지 않았다.
- 대조한 씀씀 정본: RULE-EDIT-001~010, RULE-REF-001, CONTRACT-DOMAIN-NOTE. 코드: `src/widgets/note-editor/ui/*`, `src/features/scripture/insert/model/autocomplete.ts`

## 5. 에디터 구조

**블록 에디터가 아니다.** 본문 전체가 `UITextView` 하나이고, 성경 카드는 텍스트 안의 첨부(`NSTextAttachment`, 접근성 값에서 `￼`로 보임)다. 목록 기호도 `⦁ ` 문자가 텍스트에 그대로 들어간다.
씀씀은 반대로 블록 배열을 직접 그리고 문단마다 `TextInput`을 쓴다(ADR-0001). 이 차이 때문에 아래에서 Spirit Notes가 공짜로 얻는 기능(여러 문단 선택, iOS 표준 편집 메뉴, 단락을 넘는 커서 이동)이 있고, 반대로 Spirit Notes 쪽에는 경계 버그가 있다(§8).

## 7. 성경 카드 상세

### 7.1 참조 인식 (space 트리거)

| 입력 | 결과 | 씀씀 (코드 기준) |
|---|---|---|
| `Rom 8:28 ` | ✅ Romans 8:28 — 축약을 정식명으로 바꿔 표시 | ✅ |
| `1 Cor 13:4-7 ` | ✅ 범위, 절마다 위첨자 번호 | ❌ 숫자로 시작하는 영어 책명은 인식 못함 (drift B10/B11) |
| `read john 3:16 today` (문장 중간, 소문자) | ✅ `read ` / 카드 / `today`로 3분할 | ✅ 같은 모델 (RULE-EDIT-002) |
| `Ps 23 ` (장만) | ❌ 무시 | ❌ 같음 |
| `Jn3:16 ` (공백 없음) | ❌ 무시 | ✅ `\s?` 허용 |
| `Eph 2:8,9 ` (쉼표 나열) | ⚠️ 2:8만 카드가 되고 **`,9 `가 사라진다** | ❌ 무시 (텍스트는 남는다) |
| `Matt 5:48-6:2 ` (장을 넘는 범위) | ❌ 무시 | ❌ 같음 |
| `요 3:16 ` (한국어) | ❌ 무시 (1차 조사) | ✅ |
| 참조가 든 문장 붙여넣기 | ❌ 변환 안 됨. 붙여넣은 글에 현재 서식(밑줄)이 입혀진다 | ✅ 차이 구간을 검사하므로 붙여넣기도 변환 (RULE-EDIT-001) |

삽입 후 캐럿은 카드 다음 새 줄로 간다(씀씀 RULE-EDIT-003과 같음). 빠르게 연속 입력하면 비동기 삽입과 경합해 **뒤이어 친 글자가 줄 앞쪽에 들어가는** 순서 꼬임이 재현됐다.

### 7.2 카드 조작

- **탭 / 길게 누르기** → "Scripture" 시트(둘 다 같음. 드래그 이동이나 컨텍스트 메뉴는 없음)
  - 본문 미리보기
  - **휠 피커 5개**: 책 · 장 : 시작절 – 끝절 · 번역본. 끝절 휠은 시작절 이상만 고를 수 있다. 바꾸면 미리보기가 **즉시** 바뀐다
  - `Update Verse` — 변경이 있을 때만 활성화
  - `Highlight` → 미리보기에서 범위를 선택하고 8색 + 지우기 중 고른다. **카드 안 구절 일부만 색칠할 수 있고** 노트의 카드에 그대로 반영된다
- **Backspace** (카드 바로 뒤 줄 맨 앞): 1회 = 카드 뒤의 개행 삭제, 2회 = **카드 전체 삭제**. 원래 입력한 참조 텍스트로 되돌아가지 않는다
- **`+NIV` 버튼** = 기본 번역본 선택 시트(설치됨 / 다운로드 가능: ESV·NLT·NKJV·CSB·KJV·MSG…). `RL` 배지는 red-letter를 지원한다는 표시. 수동으로 구절을 삽입하는 버튼은 **아니다**

### 7.3 목록 미리보기에 나오는 모습

노트 목록의 본문 미리보기에서 카드는 **참조 라벨로 평문화**된다("… Romans 8:28 1 Corinthians 13:4-7 …"). 목록 기호 `⦁`는 그대로 남는다. → 씀씀의 `citedRefs`·`stripInlineMarks` 평문화와 같은 접근이다.

## 8. 관찰된 결함 (따라 하지 말 것)

1. **카드 시트에서 `Update Verse`를 누르자 앱이 멈췄다**(UI 응답 없음, 크래시 로그 없음, 강제 종료). 재실행해 보니 그 직전의 카드 형광펜 적용까지 **저장되지 않았다.** 반면 본문 텍스트 수정은 저장되어 있었다 → 카드 속성 변경은 텍스트 자동저장 경로를 타지 않는 것으로 보인다
2. `Eph 2:8,9` — 인식하지 못한 꼬리 `,9 `를 조용히 삭제한다(데이터 손실)
3. 빠른 연속 입력 중 카드가 삽입되면 캐럿 위치가 꼬인다

## 9. 씀씀 도입 후보 (에디터 한정)

1차 G6(형광펜)을 구체화하고 새 항목을 더한다. 판단 기준은 1차와 같다(OTA로 나갈 수 있는지, 스키마가 바뀌는지).

**추천 묶음**: E1 + E2. 둘 다 이미 있는 저장 형식에 입력 UI만 붙이는 일이라 스키마도 정책도 건드리지 않는다. 정본 갱신 대상은 RULE-EDIT-010의 "입력 UI 없음" 문단과 CONTRACT-DOMAIN-NOTE의 "입력할 UI는 없다" 줄이다. 그다음은 E3(오타 수정 경로는 어르신 사용자에게 체감이 크다).
